# 🟢 1. What is String Interning in Python?

👉 **String interning = optimization where Python stores only one copy of identical immutable strings**

Instead of creating multiple same strings, Python **reuses memory**.

---

## ✅ Example

```python
a = "hello"
b = "hello"

print(a is b)   # True (mostly)
```

👉 Both `a` and `b` may point to **same memory location**

---

## 🧠 Why Python does this?

* Saves memory
* Faster comparison (`is` becomes quick)
* Works well because strings are **immutable**

---

# 🟢 2. When Interning Happens Automatically?

Python automatically interns:

### ✅ 1. Short strings

```python
a = "hi"
b = "hi"
print(a is b)  # True
```

---

### ✅ 2. Strings with only letters, numbers, underscore

```python
a = "hello123"
b = "hello123"
print(a is b)  # True
```

---

### ❌ Not guaranteed for:

```python
a = "hello world"
b = "hello world"
print(a is b)  # May be False
```

👉 Because of space / runtime creation

---

# 🟢 3. Manual Interning

You can force interning using:

```python
import sys

a = sys.intern("hello world")
b = sys.intern("hello world")

print(a is b)   # True ✅
```

---

# 🟢 4. Is there String Constant Pool like Java?

👉 ✅ **Conceptually YES (similar), but not exactly same as Java**

---

## 🔸 In Java:

* There is a strict **String Constant Pool**
* All literals go into pool automatically

---

## 🔸 In Python:

* No official “pool” name like Java
* But **interning behaves similarly**
* Managed dynamically by Python interpreter

👉 So you can say in interview:

✔️ *“Python does not have an explicit String Constant Pool like Java, but it uses string interning which provides similar optimization.”*

---

# 🟢 5. Important Behavior (VERY TRICKY)

## 🔥 Compile-time vs Runtime

```python
a = "hello" + "world"
b = "helloworld"

print(a is b)   # True ✅
```

👉 Because Python optimizes at **compile time**

---

```python
a = "hello"
b = "world"

c = a + b

d = "helloworld"

print(c is d)   # False ❌
```

👉 Runtime creation → new object

---

# 🟢 6. Memory Visualization

```
Interned:
a ─┐
   ├──> "hello" (same object)
b ─┘

Not Interned:
c ──> "helloworld" (new object)
d ──> "helloworld" (different object)
```

# 🟢 7. 🔥 Tricky Interview Questions

---

## ❓ Q1

```python
a = "python"
b = "python"

print(a is b)
```

👉 ✅ **True** (interned)

---

## ❓ Q2

```python
a = "python is good"
b = "python is good"

print(a is b)
```

👉 ⚠️ **May be True or False**

---

## ❓ Q3

```python
a = "py" + "thon"
b = "python"

print(a is b)
```

👉 ✅ **True** (compile-time optimization)

---

## ❓ Q4

```python
a = "py"
b = "thon"

c = a + b
d = "python"

print(c is d)
```

👉 ❌ **False** (runtime)

---

## ❓ Q5

```python
import sys

a = sys.intern("hello world")
b = sys.intern("hello world")

print(a is b)
```

👉 ✅ **True**

---

## ❓ Q6 (VERY IMPORTANT)

```python
a = "hello"
b = a

print(a is b)
```

👉 ✅ **True** (same reference)

---

## ❓ Q7

```python
a = "hello"
b = "he" + "llo"

print(a is b)
```

👉 ✅ **True** (optimized)

# 🟢 8. Key Takeaways

* Interning = reuse same string object
* Happens automatically for simple strings
* Use `sys.intern()` for control
* Python ≠ Java pool, but similar idea
* `==` → value comparison (safe)
* `is` → reference comparison (tricky)

---

# 🚀 Pro Interview Tip

👉 If interviewer asks:

**“Should we use `is` for string comparison?”**

✔️ Answer:

> ❌ No, always use `==` because `is` depends on interning and may give inconsistent results.
